## 1. なぜ「AI使用禁止」のルールは破綻するのか？

「レポートへのAI利用を一切禁止する」と通達しても、生徒は隠れて使い、教員は「これはAIが書いたのか？」と疑心暗鬼になって検出ツールとにらめっこする不毛なイタチごっこが始まります。
大切なのは、AIの利用を禁止することではなく、**『AIには絶対に書けない、現場の一次情報（自分の五感の記録・失敗した生データ）』**を評価の核に据えることです。

---

## 2. AI丸写しを無力化するルーブリック評価プロンプト

以下のプロンプトで、生徒の実習レポートを「一次情報の有無」に基づいて客観評価する基準表を出力します。

### 【一次情報重視ルーブリック生成プロンプト】
```text
# 命令
以下の【実習・課題研究テーマ】において、AIによる表面的なまとめを排し、生徒自身の生きた学びを正当に評価する「4段階ルーブリック」を作成してください。

# 【実習・課題研究テーマ】
[例: 旋盤加工実習 / プログラミング基礎 / 地域アンケート調査]

# ルーブリックの4観点
1. A（秀）: 自分が作業中に直面した「失敗」「予想外の現象」「五感の気づき」が具体的に記述され、AIの一般的解説と比較・考察されている。
2. B（優）: 実習の手順とデータは正確に記録されているが、考察が一般的な理論のまとめにとどまる。
3. C（可）: データや考察の記述が抽象的で、本人の直接的な試行錯誤の形跡が薄い。
4. D（再提出）: インターネットやAIの出力をそのまま貼り付けた痕跡があり、生データとの乖離がある。
```

### 【入力実例】
```text
工業高校：旋盤での鉄鋼切削加工実習。
```

### 【AIによる出力実例】
```text
A評価基準: 「切削時の煙の匂いや切削音の変化、バイトの送り速度を上げた際に削り面が粗くなった失敗データが記録され、なぜその現象が起きたかが考察されていること」。AIには決して書けない「泥臭い現場の事実」を最高評価に設定。
```

## 3. 授業での指導アナウンス（3分）

* **課題提示時: 「ネットやAIで調べた綺麗なまとめはいりません。あなたが実際に失敗したこと、手が震えたこと、予想と違ったことだけを書いてください。」
* **レポート回収時: 「AIを使った人は、AIに何を聞いて、どこが自分の現場体験と違っていたかを1行添えて提出してね。」
* **フィードバック: 生徒の失敗エピソードを取り上げて「この気づきこそ現場のプロの目線だ！」と教室全体で称賛。

## 4. やってはいけないNG指導と現場のリカバリー策

* **やってはいけないNG指導：AI検出ソフトのスコアだけで生徒を犯人扱いする**  
  AI検出ツールは誤判定（偽陽性）が極めて多く、自力で一生懸命書いた生徒を「AIで書いただろ」と決めつけて冤罪を生むリスクがあります。ツールの判定で叱るのではなく、レポートの中身について「ここ面白かったけど、実際どういう感触だった？」と直接口頭で質問してください。

* **現場のリカバリー策：「AIとの壁打ち対話ログ」の添付義務化**  
  AIを使った場合は、プロンプトとAIの回答のスクリーンショットをレポート末尾に添付させます。AIの出したアイデアをどう取捨選択したかを評価対象にすることで、情報活用能力の育成に昇華させます。
